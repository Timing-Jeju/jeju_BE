## 1) 서비스 기획배경 및 필요성

### 1. 서비스 기획 배경

제주도는 관광지가 넓게 분산되어 있어 렌터카 없이 이동하는 여행자에게 일정 관리 난이도가 높다. 특히 버스 중심으로 여행하는 뚜벅이 관광객은 버스 배차 간격, 정류장 위치, 정류장까지의 도보 시간, 환승 가능 여부에 따라 하루 일정이 쉽게 틀어진다. 관광지 정보는 충분히 찾을 수 있지만, 실제 여행 중에는 "지금 더 머물러도 되는지", "몇 시까지 출발해야 다음 버스를 놓치지 않는지", "버스를 놓치면 어떤 일정을 줄여야 하는지"를 판단하기 어렵다.

기존 지도 서비스는 특정 구간의 길찾기에는 강하지만, 하루 전체 관광 일정이 버스 시간에 맞게 운영되는지까지 관리해주지는 않는다. 일반 여행 추천 서비스도 가볼 만한 장소를 추천하지만, 다음 버스 시간과 남은 체류 시간을 함께 고려한 실행 가능한 추천에는 한계가 있다.

타이밍제주는 이러한 문제를 해결하기 위해 한국관광공사 TourAPI 관광정보와 제주 버스 데이터를 결합해, 제주 뚜벅이 여행자가 버스 시간 때문에 일정을 실패하지 않도록 돕는 웹·앱 서비스로 기획하였다.

### 2. 서비스 필요성

제주 뚜벅이 여행자의 핵심 불편은 관광지 부족이 아니라 **이동 타이밍 실패**다. 버스를 한 번 놓치면 다음 배차까지 긴 대기 시간이 발생할 수 있고, 한 구간의 지연이 이후 관광지 체류 시간과 숙소 도착 시간까지 영향을 준다.

타이밍제주는 사용자가 입력한 여행 일정에 대해 다음 정보를 제공한다.

- 관광지별 가까운 정류장 후보
- 시간표 기준 출발 권장 시각
- 다음 버스를 놓쳤을 때 추가 대기 위험
- 일정 안전도 점수
- 남는 시간 안에 가능한 주변 관광지 추천
- 일정 지연 시 대체 일정 및 체류시간 조정안

이를 통해 제주를 처음 방문하는 관광객도 버스 중심 일정을 더 예측 가능하게 운영할 수 있다. 또한 렌터카 이용이 어려운 여행자, 청년 여행자, 외국인 관광객에게도 제주 관광 접근성을 높일 수 있다.

## 2) 서비스 개요

### 1. 기획 서비스 소개

**타이밍제주는 TourAPI 관광정보와 제주 버스 시간표를 결합해, 렌터카 없이 제주를 여행하는 뚜벅이의 일정 실패를 줄이는 제주 특화 웹·앱 서비스이다.**

### 2. 기획 서비스 주요 기능

**첫째, TourAPI 기반 관광지 매칭**

사용자가 "10시에 제주공항 도착, 함덕, 월정리, 성산일출봉을 가고 싶어"처럼 자연어로 입력하면, 서비스는 한국관광공사 TourAPI의 키워드 검색과 관광지 정보를 활용해 입력 장소를 실제 관광지 후보와 매칭한다. 관광지명, 주소, 좌표, 이미지, 소개 정보를 일정 카드에 표시하고, 장소명이 애매한 경우 후보를 제시해 사용자가 선택하도록 한다.

**둘째, 버스 시간표 기반 일정 안전도 계산**

각 관광지 좌표와 제주 버스 정류소 정보를 비교해 가까운 정류장 후보를 찾고, 시간표 데이터를 기준으로 다음 목적지까지 이동 가능한 버스 후보를 계산한다. 정류장까지의 도보 시간과 안전 버퍼를 반영해 "몇 시까지 출발해야 하는지"를 안내한다.

예시:

| 구간 | 출발 권장 | 후보 버스 | 놓쳤을 때 위험 | 상태 |
|---|---:|---:|---:|---|
| 함덕해수욕장 -> 월정리해변 | 12:10 | 12:37 | 약 42분 대기 | 위험 |

**셋째, 버스 놓침 방지 라이브 타임라인**

여행 당일에는 현재 시각을 기준으로 일정을 초록·노랑·빨강 상태로 보여준다. 초록은 여유, 노랑은 출발 준비, 빨강은 일정 위험 상태를 의미한다. 실시간 화면은 서버가 계산한 출발 권장 시각과 시간표 후보를 기준으로 빠르게 갱신하며, 불필요한 AI 호출 없이 안정적으로 동작하도록 설계한다.

**넷째, 남는 시간 및 버스 놓침 상황의 주변 추천**

버스를 놓쳐 다음 버스까지 시간이 생기거나, 관광지를 예상보다 빨리 둘러본 경우 TourAPI 위치기반 관광정보를 활용해 남은 시간 안에 가능한 주변 관광지, 카페, 포토스팟을 추천한다. 단순 거리순 추천이 아니라 "왕복 이동 시간 + 예상 체류 시간 + 다음 버스 복귀 버퍼"를 계산해 다음 일정에 늦지 않는 후보만 보여준다.

**다섯째, 일정 지연 시 복구안 제공**

관광지 체류 시간이 길어져 일정이 밀리면, 이후 구간의 버스 후보와 체류 가능 시간을 다시 계산한다. 사용자가 필수 방문지로 설정한 장소는 유지하고, 선택 관광지의 체류 시간을 줄이거나 제외하는 복구안을 제시한다. OpenAI API는 서버가 계산한 사실을 기반으로 복구안을 자연어로 설명하는 역할을 수행한다.

### 3. 서비스 차별성

타이밍제주는 일반 관광 추천 앱, 지도 앱, AI 여행 플래너와 역할이 다르다.

| 구분 | 기존 서비스 | 타이밍제주 |
|---|---|---|
| 지도 앱 | A에서 B까지 경로 안내 | 하루 전체 일정의 버스 타이밍 관리 |
| 관광 추천 앱 | 가볼 만한 장소 추천 | 남은 시간 안에 실제 가능한 장소 추천 |
| AI 여행 플래너 | 그럴듯한 일정 생성 | TourAPI와 시간표 기반으로 위험도 검증 |

특히 OpenAI API를 사용하더라도 버스 시간이나 경로 가능 여부를 AI가 임의로 생성하지 않는다. 버스 시간, 출발 권장 시각, 위험도는 서버의 계산 엔진이 담당하고, OpenAI는 자연어 일정 분석과 설명 보조 역할을 담당한다.

핵심 원칙은 다음과 같다.

```text
버스 시간과 경로 판단은 서버가 계산하고,
AI는 계산된 사실을 이해하기 쉽게 설명한다.
```

### 4. 서비스 내 지역 특화 관련 사항

타이밍제주는 전국 범용 여행 서비스가 아니라 **제주 지역 특화 서비스**다. 제주 관광은 관광지 간 거리가 길고, 동서남북 관광권이 넓게 나뉘며, 렌터카 여부에 따라 여행 경험이 크게 달라진다. 특히 뚜벅이 관광객은 버스 배차와 정류장 위치를 고려하지 않으면 일정 실패 가능성이 높다.

본 서비스는 제주 동쪽 대표 관광 코리도어를 MVP 범위로 설정한다.

- 제주공항
- 함덕해수욕장
- 월정리해변
- 성산일출봉
- 섭지코지
- 성산/서귀포 숙소권

이 범위는 제주 뚜벅이 관광객이 많이 선택하는 동선이며, 버스 배차 간격에 따른 일정 위험을 명확히 보여줄 수 있다. 향후 제주 전역으로 확대하되, 공모전 개발 기간에는 검증 가능한 코리도어 중심으로 완성도를 높인다.

## 3) 데이터 활용 방안

### 1. 활용 예정 한국관광공사 OpenAPI

활용 예정 OpenAPI는 **한국관광공사 국문 관광정보 서비스 TourAPI**다.

주요 활용 기능:

- 키워드 검색
- 위치기반 관광정보
- 지역기반 관광정보
- 이미지정보
- 공통정보
- 소개정보
- 행사정보
- 숙박정보

TourAPI는 서비스의 핵심 데이터다. 사용자가 입력한 관광지명을 실제 관광지 후보와 매칭하고, 관광지 좌표를 기준으로 주변 정류장을 찾으며, 남는 시간 추천 후보를 생성하는 데 사용한다.

### 2. 데이터 활용 방식

| 데이터 | 활용 방식 |
|---|---|
| TourAPI 키워드 검색 | 사용자가 입력한 장소명을 실제 관광지 후보로 매칭 |
| TourAPI 위치기반 관광정보 | 현재 위치 주변의 관광지, 음식점, 문화시설 후보 조회 |
| TourAPI 이미지정보 | 추천 카드와 일정 카드에 관광지 이미지 표시 |
| TourAPI 공통/소개정보 | 관광지 설명, 주소, 좌표, 카테고리 표시 |
| TourAPI 숙박정보 | 숙소 주변 일정 추천 및 도착지 설정에 활용 |
| TourAPI 행사정보 | 여행 날짜에 맞는 주변 행사 후보 추천 |

추가 활용 데이터:

| 데이터 | 활용 방식 |
|---|---|
| 제주 버스 정류소 기본 정보 | 관광지 주변 정류장 후보 탐색 |
| 제주 버스 노선 기본 정보 | 구간별 노선 후보 표시 |
| 제주 버스 시간표 정보 | 출발 권장 시각, 대기 위험, 놓쳤을 때 추가 대기 계산 |
| Kakao Maps Web API | 지도, 관광지/정류장 마커 표시 |
| OpenAI API | 자연어 일정 파싱, 일정 위험 설명, 복구안 설명 |

데이터 정확도 관리:

- TourAPI 장소명이 여러 개 매칭되면 사용자 선택 UI를 제공한다.
- 정류장은 "가까운 정류장 후보"로 표현하고, 실제 승차 위치는 지도에서 확인하도록 한다.
- MVP는 시간표 기반 안내를 제공하며, 실시간 지연·결행을 보장하지 않는다는 점을 화면에 명시한다.
- 데이터 상태 화면을 통해 TourAPI 호출 성공 시각, 버스 시간표 기준일, fallback 여부를 표시한다.

## 4) 서비스 발전 방향

### 1. 개발 서비스 향후 발전방향

**1단계: 공모전 MVP 완성**

공모전 개발 기간에는 제주 동쪽 코리도어 중심으로 핵심 기능을 완성한다. 주요 목표는 TourAPI 장소 매칭, 시간표 기반 출발 권장 시각 계산, 일정 안전도 표시, 버스 놓침 시 주변 추천, 일정 지연 시 복구안 제공이다.

**2단계: 제주 전역 확장**

MVP에서 검증한 구조를 바탕으로 제주 전역의 정류장, 노선, 시간표 데이터를 확대 적용한다. 노선별 정류장 순서와 시간표 정합성을 검증한 뒤, 더 많은 지역의 뚜벅이 여행 일정을 지원한다.

**3단계: 실시간 보정 및 다국어 안내**

정류장별 도착예정 정보 또는 버스 위치 데이터 활용 가능성이 확보되면 시간표 기반 안내에 실시간 보정을 추가한다. 또한 외국인 관광객을 위해 한국어 일정 안내를 영어·중국어·일본어 등으로 제공하고, "이 정류장에서 하차하세요", "지금 이동을 시작하세요" 같은 실용 문장을 다국어로 안내한다.

**4단계: 지역관광 운영 데이터로 확장**

사용자가 어떤 구간에서 자주 지연되는지, 어떤 관광지에서 대기 시간이 자주 발생하는지 분석하면 제주 지역 관광 운영에도 활용할 수 있다. 향후에는 RTO나 지자체가 뚜벅이 관광객의 이동 불편 구간을 파악하고, 관광지 분산 방문과 대중교통 기반 관광 활성화에 참고할 수 있는 대시보드로 발전시킬 수 있다.

기대효과:

- 제주 뚜벅이 관광객의 버스 대기 시간 감소
- 일정 실패와 관광지 포기 경험 감소
- 렌터카 없이도 가능한 제주 여행 경험 확대
- TourAPI 관광정보 활용도 증대
- 제주 지역특화 관광 서비스 경쟁력 강화
- 향후 제주 RTO와 연계 가능한 관광 이동 데이터 기반 마련
