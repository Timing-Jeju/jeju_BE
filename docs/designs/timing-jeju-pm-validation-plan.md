작성일: 2026-05-21  
역할: PM 세션 / 기술 검수자  
상태: 구현 전 검증 운영안

## 목적

타이밍제주는 예선 통과 후 구현 가능성을 증명해야 하는 단계다. 이 문서는 메인 세션이 직접 모든 구현을 떠안지 않고, 검증 작업을 작은 단위로 나눠 별도 작업 세션에 전달하고, 결과를 리뷰해 MVP 범위와 기술 결정을 확정하기 위한 운영 문서다.

```text
제출한 말이 실제 데이터와 코드로 계산되는가?
```

## 현재 PM 판단

### 이미 비교적 강한 부분

| 항목 | 상태 | 근거 |
|---|---|---|
| 문제 정의 | 강함 | 예선 통과 제안서가 "제주 뚜벅이 이동 타이밍 실패" 문제를 인정받았다. |
| MVP 방향 | 강함 | 제주 동쪽 코리도어, 시간표 기반, 실시간 미의존으로 범위가 좁다. |
| 로컬 POC | 부분 검증 | `poc/timing-jeju-corridor-poc.mjs`에서 100/38/81 점수와 +40~48분 리스크가 재현된다. |
| AI 사용 경계 | 강함 | `TransitEngine owns facts. OpenAI explains facts.` 원칙이 명확하다. |
| 앱 기술 방향 | 강함 | Expo 앱 + Spring Boot API + PostgreSQL/PostGIS + OpenAI Responses API로 정리됨. |

### 아직 약한 부분

| 항목 | 상태 | 왜 위험한가 |
|---|---|---|
| TourAPI 실호출 | 미검증 | API 키 없이 제출본 수준의 장소 매칭이 실제 응답 필드로 가능한지 확인 필요. |
| 제주 버스 정류소 API | 미검증 | 정류장 좌표, 정류장 ID, 명칭 정규화 필드가 실제로 충분한지 확인 필요. |
| 제주 노선/정류장 순서 | 고위험 | 임의 출발지-목적지 라우팅에 필요한 노선별 정류장 순서 품질이 아직 확정되지 않았다. |
| 제주 버스 시간표 import | 중위험 | XLSX 다운로드 구조와 컬럼 형태가 구현 가능한지 샘플 import 검증 필요. |
| 실시간 버스 API | MVP 제외 후보 | 공공데이터상 XML/LINK 기반이고 트래픽/필드/정확도 검증이 필요하다. |
| 지도 구현 | 중위험 | 네이티브 지도 SDK를 쓰면 앱 빌드 리스크가 커진다. MVP는 딥링크/WebView 우선 검증 필요. |
| DB 스키마 | 초안 필요 | TourAPI, 정류장, 시간표, 일정, 리스크 이벤트의 최소 저장 구조 확정 필요. |
| API 계약 | 초안 필요 | Expo 앱과 Spring API가 공유할 DTO를 먼저 고정해야 병렬 구현이 가능하다. |

## PM 운영 방식

1. 메인 세션이 검증 항목을 작게 나눈다.
2. 각 검증 세션에는 하나의 질문만 맡긴다.
3. 작업 세션은 공식 문서, 실제 요청/응답 예시, 간단한 코드 POC 또는 테스트 계획을 남긴다.
4. 메인 세션은 결과를 아래 기준으로 판정한다.
5. 판정 결과만 MVP 설계 문서와 구현 backlog에 반영한다.

## 판정 등급

| 등급 | 의미 | PM 결정 |
|---|---|---|
| GO | 공식 문서와 최소 POC가 모두 맞다. | MVP에 포함한다. |
| GO_WITH_GUARDRAIL | 가능하지만 실패 조건이 명확하다. | fallback, cache, fixture, UI 고지를 붙여 포함한다. |
| DEFER | 가능성은 있으나 본선 MVP에 과하다. | Phase 2로 내린다. |
| NO_GO | 데이터/인증/비용/구현 리스크가 MVP를 깨뜨린다. | MVP에서 제거하고 대체안을 선택한다. |
| NEEDS_MORE_PROOF | 문서만 있고 실제 응답/샘플 검증이 부족하다. | 다음 검증 세션을 추가한다. |

## 작업 세션 공통 지시

모든 작업 세션은 아래 규칙을 따른다.

- 공식 문서를 1순위로 확인한다.
- 블로그, 개인 글, 예전 예제만으로 결론 내리지 않는다.
- 가능하면 실제 요청 URL, 파라미터, 응답 필드명을 확인한다.
- API 키가 없으면 실호출 대신 공식 예시와 mock 응답 구조를 정리하고, 실호출에 필요한 환경변수를 명시한다.
- 비용/쿼터/인증 방식은 반드시 별도 항목으로 쓴다.
- MVP에 넣을지, 우회할지, Phase 2로 미룰지 판단한다.
- 결과는 메인 세션이 바로 비교할 수 있게 같은 형식으로 작성한다.
